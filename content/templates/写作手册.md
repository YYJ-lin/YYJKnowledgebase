# 写作手册

这份文件放在 `content/private/` 里，**站点构建时会跳过私密目录**，所以只有你在 Obsidian 里能看到，线上不会出现。

---

## 一、第一次用 Obsidian（只做一次）

1. 双击 U 盘里的 `Obsidian\Obsidian.exe`
2. 点「打开本地仓库 / Open folder as vault」→ 选 `<U盘>\知识库\站点\content`
3. 右上角齿轮 → 设置里改三处：

| 设置位置 | 改成 |
| --- | --- |
| 文件与链接 → 附件默认位置 | 当前文件夹下的 `attachments` 子目录 |
| 文件与链接 → 新建笔记位置 | 当前文件所在文件夹 |
| 模板 → 模板文件夹 | `templates` |

---

## 二、写一篇新文章（每次）

### 第 1 步：去哪写

左侧文件列表里，**点进要放的文件夹**，然后按 `Ctrl + N`（或在文件列表空白处右键 → 新建笔记）。

| 文章类型 | 放到 |
| --- | --- |
| 项目记录 / 技术手记 | `tech` |
| ERPNext 教程 | `kb/erpnext` |
| WordPress 教程 | `kb/wordpress` |
| 应用介绍 | `kb/apps` |
| 行业常识 | `kb/industry` |
| 工具推荐 | `tools` |

### 第 2 步：文件起名

用英文小写 + 连字符，例如 `install-docker`、`wordpress-theme`。

文件名会变成网址的一部分：`kb/erpnext/install-docker` → 网址 `/kb/erpnext/install-docker`

### 第 3 步：填属性（就填这几个）

在文件最上面写：

```yaml
---
标题: 从零装一个 WordPress
描述: 一台空服务器从装系统到站点能访问的全过程
日期: 2026-10-22
标签: [wordpress, 建站]
---
```

- **标题**、**描述**、**日期**、**标签** 都写中文就行
- 标签写 1–3 个，用来生成「相关文章」和标签页
- 别手写 `title:`、`description:` 这些英文——中文的就行

### 第 4 步：写正文

直接写在属性下面。骨架参考（照抄改内容）：

```markdown
一句话说明这篇讲什么、适用什么场景。

## 环境

- 系统：Ubuntu 24.04
- 版本：WordPress 6.6

## 步骤

### 1. 装好运行环境

说明这一步做什么，为什么这么做。

```bash
apt install -y nginx
```

### 2. 配置站点

## 踩到的坑

> [!warning] 权限问题
> 现象：上传图片失败。原因：目录属主不对。解决：`chown -R www-data:www-data wp-content`。

## 结果

最后怎么验证成功。
```

**注意**：正文里**不要再写 `# 一级标题`** —— 页面大标题由属性里的「标题」生成。

### 第 5 步：插入图片

1. 把图片**直接拖进正文**（或复制粘贴）；
2. Obsidian 会问放哪 —— 选 `attachments`（第一次设置好之后就自动了）；
3. 生成的写法是 `![[图片名.png]]`，站点能正常显示。

> 图片别用外链，会失效。

## 三、正文里常用的几种写法

### 小标题

```markdown
## 步骤
### 1. 第一步
```

### 重点 / 列表 / 表格

```markdown
**加粗重点**
*斜体*
~~删除线~~

- 项目一
- 项目二

1. 第一步
2. 第二步

| 列一 | 列二 |
| --- | --- |
| 值 | 值 |
```

### 提示框（四种最常用）

```markdown
> [!tip] 小技巧
> 内容

> [!warning] 注意
> 内容

> [!note] 说明
> 内容

> [!danger] 危险操作
> 内容
```

### 代码

````markdown
```bash
docker compose up -d
```
````

### 链接到另一篇文章

```markdown
[[tech/install-docker]]
[[tech/install-docker|看这篇：安装 Docker]]
```

写对路径即可，**鼠标悬停会自动弹出那篇文章的预览**。

### 折叠块

```html
<details><summary>点开看更多</summary>
里面的内容
</details>
```

## 四、发布

1. 双击 `同步最新.cmd`（如果上次是在别的电脑上写的，先同步）
2. 写完双击 `发布到网站.cmd`
3. 看到「完成」后等 2–10 分钟，刷新 https://yyj-lin.github.io/YYJKnowledgebase/

## 五、常见问题

| 现象 | 原因 | 怎么修 |
| --- | --- | --- |
| 页面上标题是文件名（如 install-docker） | 属性里没写「标题」 | 加上 `标题: 中文标题` |
| 文章没出现在左侧目录 | 放错文件夹，或者没发布 | 确认在 `tech`/`kb`/`tools` 下，然后发布 |
| 图片显示不出来 | 图片不在 `attachments`，或用了外链 | 拖进正文让 Obsidian 自动放到 `attachments` |
| 链接点开 404 | 路径写错，或文件改过名 | 路径按 `文件夹/文件名` 写；改名要加「别名」 |
| 文章里有 `==高亮==` 这种原文 | 站点不支持高亮语法 | 改用 `**加粗**` |
| 预览里看到的是旧内容 | 没跑 `发布到网站.cmd`，或者构建还没完成 | 等几分钟再刷新 |
| 发布提示 Permission denied | 网络到不了 GitHub | 开 VPN 再试 |

## 六、几条经验

1. **先写起来，别管结构**：一开始不用纠结标签、链接，写 3 篇之后自然知道该怎么分；
2. **一篇只讲一件事**：标题写清「解决什么问题」，比文艺标题有用；
3. **命令要能复制**：代码块里放完整命令，注明在哪台机器执行；
4. **踩坑必写**：读者搜的就是"报错信息"，把现象和原因写进去；
5. **改文件名要加别名**：属性里写 `别名: [旧路径]`，否则旧链接会 404。
